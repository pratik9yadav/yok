# yok: train a small model for free

The owner wants Claude to do the work when asked, and answers in short, simple English
(they often write from a phone). Lead with the result, then the one next step.

## What is here
A notebook that fine-tunes Qwen3 4B (QLoRA, Unsloth) to read what a shopkeeper said on a
call and return JSON: `in_stock`, `price_inr`, `delivery`, `alternative`. It is part of the
WIMB project (pratik9yadav/WIMB). `data/train.jsonl` (training set v2, 1,300 rows) is generated by
`make_data.py` from the real data in `data/real/`; the 151 real Hindi xPQA rows are added at training
time; `data/train_v1.jsonl` is the first 400 made-up rows (for comparison). Held-out sets, never
trained on: `data/test.jsonl` (30), `data/hard_test.jsonl` (56), `data/fresh_test.jsonl` (60, blind).
Never use held-out rows for ideas or phrasing when changing `make_data.py`; tests check for leakage.

`train_colab.ipynb`, `try_model.ipynb` and `ask_model.ipynb` are generated: edit `build_notebook.py`, `score.py`
or `data/`, then run `python build_notebook.py` and `python -m pytest`. Never edit the notebooks by hand.

## "Train the model" / "run it"
Preferred: GitHub Actions. The workflow `.github/workflows/train.yml` ("Train on Kaggle") reads
the repository secret `KAGGLE_API_TOKEN` and runs `run_on_kaggle.py` on a GitHub runner. Start
it with the GitHub tools (workflow_dispatch on `main`), wait for it to finish, then read the job
log: it prints the before → after scores and the mistakes. If the secret is missing, the
owner adds it at https://github.com/pratik9yadav/yok/settings/secrets/actions/new.

From this container instead (needs kaggle.com allowed and the token in the environment):
1. Check `KAGGLE_API_TOKEN` is set and kaggle.com is reachable. If not, tell the owner the
   one-time setup in README.md ("Or let Claude run it for you"); don't ask for the token in chat.
2. `pip install -r requirements-dev.txt`, then run `python run_on_kaggle.py` in the
   background (about 40 minutes; it exits when the run ends).
3. Report the before → after scores and the remaining mistakes from
   `kaggle_output/results.json`. If it failed, read the log in `kaggle_output/`, fix the
   cause, run the tests, push, and run again.
4. The model files (`*.Q4_K_M.gguf`, `Modelfile`, `lora/`) are in the Kaggle run's Output tab.

Colab instead: the owner opens
https://colab.research.google.com/github/pratik9yadav/yok/blob/main/train_colab.ipynb,
runs it, and saves it back with File → Save a copy in GitHub; then read its outputs from git.

## "Ask the model" / "try it"
Run the workflow `.github/workflows/ask.yml` ("Ask the model on Kaggle") on `main` with `questions_json` =
a JSON list of `{"product", "said"}` (up to 30); wait (about 10 minutes), read the job log, and report each
answer in plain words, plus the speed (GPU and CPU only; the report says if Ollama did not use the GPU). The
job fails when an answer is missing. It runs `try_on_kaggle.py` (Ollama on the T4 with the repo's `Modelfile`;
needs a finished training run). From this container: `python try_on_kaggle.py --ask
PRODUCT SAID`. The example calls are `data/demo_questions.jsonl` (a demo, not a benchmark).
To make or refresh the owner's own notebook for asking many questions (`ask_model.ipynb`: run once, then an ask
box), run `ask.yml` with `run` = notebook (about 5 minutes; from here: `python try_on_kaggle.py --make-ask-notebook`),
then give the link `https://www.kaggle.com/code/<Kaggle user>/wimb-shop-model-ask` (the job log prints it).
After each new training run, run `ask.yml` with `run` = notebook again, so the notebook uses the new model.

## Using real data
Real call transcripts go in `data/train.jsonl`, one JSON object per line:
`{"product": ..., "said": ..., "answer": {"in_stock": ..., "price_inr": ..., "delivery": ..., "alternative": ...}}`.
Keep `data/test.jsonl` separate from training data (a test checks this).

## Results so far and what is next
See "Results" in README.md. Run 9 (v2): test 97% / hard 84% / fresh 77% after training; exported
file 97% / 79% / 70%. Run 10 (v1 control): 83% / 43% / 60%. `fresh` is the fairest number.
`results.json` in a run's output holds, per set, scores, mistakes and every raw reply. The
notebook also tests the exported GGUF through llama-server on CPU (`results_gguf.json`).
Next step that helps most: decide one rule for how full `alternative` should be (brand only, or
brand + size + item), say it in `SYSTEM` and follow it in `make_data.py` and the answer keys; and
more "paune / sava / saadhe" spoken prices in `make_data.py`. Real transcripts still beat everything.
Never take ideas or wording from the held-out sets. Then run again (about 60 minutes, free).
Use the repo's `Modelfile`, not the one Unsloth writes.

## Coder model (separate project, in `coder/`)
"Measure the coding models": run `.github/workflows/coder.yml` ("Coder model on Kaggle", inputs `models`, `limit`,
`action`; about 3½ hours), read the table at the end of the job log. Notebook: edit `coder/build.py` or
`coder/fixeval.py`, then `python coder/build.py` and `python -m pytest`. Never edit `coder/coder_eval.ipynb` by hand.
First full run: qwen3-coder:30b 73% (120/164), qwen2.5-coder:14b 64%, 7b 57%, gpt-oss:20b 55% (README).
"Train the coder model" (phase 2): run `coder.yml` with `action` train (`smoke` yes first, ~30 min); after ~5½ h a
"still running" job is normal: run `action` fetch-train. Edit `coder/build_train.py`/`coder/fixtrain.py`, then `python coder/build.py`.
Phase 2 full run: 14B 65% → 61% after QLoRA on 2,000 CommitPackFT fixes (worse); use qwen3-coder:30b as is.
"Give the coding agent a task" (phase 3): run `.github/workflows/agent.yml` ("Coding agent (free model)", input `task`;
~30–60 min); it opens a PR from `agent/run-<id>-<attempt>` (or the job summary shows its question). Review the PR; never merge
unasked. Edit `coder/agent.py`/`coder/build_agent.py`, then `python coder/build.py`; from here: `python coder/run_agent.py --task "..."`.
"Give the coding models the engineer exam" (phase 4): run `coder.yml` with `action` exam (~4½ h; "still running": `fetch-exam`),
report the table and weakest tasks from the job log. Tasks in `coder/exam/tasks/`: check with `python -m coder.exam.grade --check-references`, then `python coder/build.py`.
